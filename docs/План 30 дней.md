## 1. Вектор развития
**Агентные системы.**
Выбран потому, что проект — это инструмент, который сам собирает внешнюю
информацию, фильтрует её и отдаёт результат по запросу. Это ядро агентного
подхода: сбор → обработка → выдача. Автоматизация контента здесь — следствие,
а не цель.
## 2. Проект месяца
**Telegram-бот «Инвестиционный дайджест»** — личный инструмент, который по
названию финансового инструмента и периоду собирает посты из заданного списка
Telegram-каналов и отдаёт новости в хронологическом порядке.
**Для кого:** я сам. Это личный инструмент для подготовки к инвестиционным
решениям: сократить время чтения каналов и не пропускать важное по конкретному
активу.
## 3. Маршрут
**Сценарий, который должен работать:**
«Я пишу боту название инструмента (например, SBER) и период (месяц / квартал /
полугодие / год) → бот собирает посты из моего фиксированного списка каналов за
этот период → фильтрует по упоминанию введённой строки → отдаёт список новостей
в хронологическом порядке». Полный цикл — от запроса до выдачи — без ручной
работы.
**Логика отбора (MVP):** пост попадает в выдачу, если содержит введённую
пользователем строку (тикер или название) без учёта регистра, с простой проверкой
словоформ по основе слова. Ручной словарь синонимов — опционально, в конфиге.
**Как проверю результат:**
1. Бот отрабатывает запросы по 3–5 разным тикерам и всем четырём периодам без
   падений — подтверждено скриншотами диалогов.
2. 7 дней подряд я реально пользуюсь выдачей перед решениями.
3. Замер: время на «прочитать всё вручную» vs «прочитать выдачу бота».
4. Субъективная оценка: в выдаче есть то, на что я бы обратил внимание сам.
**Как презентую:**
- **GitHub-репозиторий** — основная форма сдачи: код проекта, README с описанием
  архитектуры, папка `screenshots/` со скриншотами работы бота (запрос → выдача
  по нескольким тикерам и периодам).
- **Онлайн-защита (опционально)** — если состоится: расшаривание экрана с живым
  прогоном бота и показом репозитория/скриншотов.
