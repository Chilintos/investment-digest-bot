## Текущая задача (единственная)

**Telegram-каналы → хронологическая сводка новостей по финансовому инструменту.**

Пользователь вводит название инструмента (тикер или название) и период
(день / неделя / месяц / квартал / полугодие / год). Система собирает посты из фиксированного
списка Telegram-каналов за этот период, фильтрует по упоминанию введённой
строки и отдаёт **список новостей в хронологическом порядке** (старые → новые).

Интерфейс: Telegram-бот с постоянной Reply-клавиатурой (снизу экрана) для выбора периода.
Выдача: дата + канал — жирным (как заголовок), полный текст, ссылка на пост.
Дополнительно: сохранение дайджеста в `Reports/` в Markdown.

Это **личный инструмент для подготовки к инвестиционным решениям**, а не
финансовый совет и не генератор рекомендаций «покупать/продавать/держать».

## Границы проекта

### Входит в MVP (делаем сейчас)
- Источники: только Telegram-каналы из фиксированного списка (в конфиге).
- Ввод: тикер/название (как написал пользователь) + период (день / неделя / месяц / квартал / полугодие / год).
- Фильтр: прямое совпадение без учёта регистра + простая проверка словоформ.
- Выдача: список новостей в хронологическом порядке (дата — канал — полный текст — ссылка); заголовок (дата + канал) — жирным.
- Интерфейс: Telegram-бот с постоянной Reply-клавиатурой (снизу экрана) для выбора периода; ввод «тикер период» в одном сообщении; inline-кнопки «Сменить тикер/период».
- Сохранение дайджеста в `Reports/` в Markdown.
- Обработка ошибок: нет упоминаний, неверный тикер, таймаут, FloodWait, сообщение слишком длинное (разбивка на части).

### Не входит в MVP (не реализовывать сейчас)
- Автоматическое формирование синонимов (Wikidata / ticker-terms, кэш, морфология).
- Сайты-источники без RSS; парсинг вёрстки.
- Консолидация новостей по темам и упорядочение по важности.
- Выделение только релевантного фрагмента новости (нарезка / LLM-извлечение).
- Анализ тональности, частота упоминаний по дням, динамика по периодам.
- Слой сигналов/правил («покупать/держать»).
- Собственный телеграм-канал, сайт-визитка, платные услуги.

### Опционально позже (после MVP, по мере необходимости)
- Ручной словарь синонимов `aliases.json` для 3–5 тикеров (уже есть для 10 тикеров).
- Сайты с RSS-лентами — после стабилизации Telegram-пайплайна.

## Архитектура решения

1. **Сбор данных — Python + Telethon (MTProto userbot).** Чтение каналов
   производится от имени Telegram-аккаунта пользователя (боты не могут
   подписываться на каналы и читать чужие каналы). Нужны `api_id` и `api_hash`
   с my.telegram.org — один раз, хранить в `.env` (файл `.env` никогда не
   коммитится и не попадает в отчёты).
2. **Хранение — CSV/SQLite.** Каждая выгрузка складывает сообщения
   (id, дата, текст, есть ли медиа) в файл данных.
3. **Фильтрация — Python (pandas):** отбор постов по введённой строке
   (тикер/название) с учётом регистра и простых словоформ; сортировка по дате.
4. **Выдача — Telegram-бот:** список новостей в хронологическом порядке +
   обязательное упоминание допущений и необходимости перепроверки фактов.

Приоритет подхода: сначала одноразовая выгрузка истории канала скриптом
(результат проверяем в Excel/CSV), потом инкрементальный сбор новых сообщений,
потом обёртка в бота.

Ограничения API: не запрашивать историю канала чаще необходимого (Telegram
ограничивает частоту запросов; при ошибках FloodWait — ждать и повторять,
а не дёргать в цикле).

## Субагенты и скиллы (демонстрация навыков Claude Code)

### Субагент: `researcher` (.claude/agents/researcher.md)
Ищет посты по финансовому инструменту и периоду в 5 заданных Telegram-каналах, возвращает хронологический список. Вызывает скилл `news-digest`.

Вызов из основного агента:
```
Agent(researcher, {"instrument": "SBER", "period": "month"})
```

### Скилл: `news-digest` (.claude/skills/news-digest/skill.md)
Основной скилл поиска: читает `docs/sources.md`, запускает `fetch` для сбора через Telethon, затем `search` через pandas с учётом синонимов из `aliases.json` и словоформ, сортирует хронологически, возвращает отформатированный список.

Использование: `/skill news-digest` загружает инструкции в контекст.

## Правила безопасности

- `api_id`, `api_hash`, токены и любые секреты держать только в `.env`;
  никогда не вставлять их в код, отчёты и вывод в чат.
- Не отправлять содержимое сообщений канала во внешние сервисы без явного
  разрешения пользователя.
- Не изменять и не удалять исходные данные: результаты анализа писать в новые
  файлы.
- Любую выдачу сопровождать предупреждением: это анализ по частному каналу,
  а не финансовый совет; перед решением перепроверять факты по первоисточникам.

## Правила кода

- Код production-ready: логирование, обработка ошибок (сети, FloodWait,
  пустые сообщения, отсутствие медиа), никакой логики «в лоб».
- Зависимости фиксировать в `requirements.txt`, запускать Python только с
  ключом `-I` при работе с недоверенными файлами.
- Комментарии и сообщения — на русском.
- Сначала уточнять: какой канал (свой или чужой), что именно выгружать
  (весь текст? только посты с тикерами? с медиа?), какой период, — потом кодить.

## Правила нейминга файлов

- Латиница, нижний регистр, слова через дефис: `fetch-channel.py`,
  `make-report.py`.
- Без пробелов и кириллицы в именах файлов и папок.
- Даты в именах — формат `YYYY-MM-DD`, в конце: `digest-2026-11-02.csv`.
- Черновики — с префиксом `tmp-`, тестовые копии — с суффиксом `-test`.
